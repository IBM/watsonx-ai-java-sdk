JSON provider discovery now falls back to the SDK's class loader when the calling thread cannot find a binding. Each Jackson binding also gives `WatsonxJacksonModule` its own package, removing the shared class name and split package introduced in 0.50.0. Applications that import this module directly must update their imports and recompile.

---

## Breaking changes

### Binding-specific `WatsonxJacksonModule` packages

`com.ibm.watsonx.ai.WatsonxJacksonModule` is replaced by a class in each binding's namespace:

| Binding dependency | New module class |
|---|---|
| `watsonx-ai-jackson2` | `com.ibm.watsonx.ai.jackson2.WatsonxJacksonModule` |
| `watsonx-ai-jackson3` | `com.ibm.watsonx.ai.jackson3.WatsonxJacksonModule` |

**Before, with either binding:**

```java
import com.ibm.watsonx.ai.WatsonxJacksonModule;
```

**After, with Jackson 2:**

```java
import com.ibm.watsonx.ai.jackson2.WatsonxJacksonModule;
```

**After, with Jackson 3:**

```java
import com.ibm.watsonx.ai.jackson3.WatsonxJacksonModule;
```

The constructor and mix-in behavior are unchanged. This move breaks source and binary compatibility for code referencing the old class. Update the import and recompile applications and integration libraries against the new SDK. Libraries compiled against the old name must also be rebuilt, even if the application's own source does not import it.

### Shared token acquisition

In 0.50.0, `IBMCloudAuthenticator.token()` and `CP4DAuthenticator.token()` invoked the REST client's synchronous `token()` method. Both authenticator entry points now use the REST client's existing `tokenAsync()` method, and `Authenticator.token()` waits for its result. The public `Authenticator.token()` and `Authenticator.tokenAsync()` signatures remain unchanged.

The synchronous REST methods have been removed:

| REST client | Removed method |
|---|---|
| `IBMCloudRestClient` | `TokenResponse token(String apiKey, String grantType)` |
| `CP4DRestClient` | `TokenResponse token(TokenRequest request)` |

Remove those overrides, including their `@Override` annotations, from custom REST providers. Implement token acquisition in `tokenAsync()`. If an existing asynchronous implementation delegates to the synchronous method, preserve that logic while moving acquisition to the asynchronous path. A provider may retain a synchronous helper of its own, but it no longer overrides an SDK method.

Code that calls either removed REST method must migrate to `tokenAsync()` and be recompiled. Existing bytecode that invokes a removed method on the REST base class can fail with `NoSuchMethodError`. A previously compiled provider that merely defines the old method may still load, but the authenticators no longer invoke it. Provider factory interfaces and `ServiceLoader` registrations are unchanged. Application code using `Authenticator.token()` continues to use the same blocking API.

Custom `IBMCloudRestClient` and `CP4DRestClient` providers must support asynchronous token acquisition even when the application calls `Authenticator.token()`. Keep those provider methods non-blocking. When acquisition requires HTTP, the default REST clients now use `HttpClient.sendAsync()` instead of `HttpClient.send()` for synchronous authenticator calls. Adapt custom HTTP clients and mocks that previously implemented or stubbed only `send()` to return the appropriate future from `sendAsync()`.

Concurrent calls on the same built-in authenticator now share one acquisition, including both CP4D IAM authentication steps. Each `tokenAsync()` call returns an independent future. A successful acquisition updates the cache even if all callers cancel their futures.

See [Token lifecycle](../authentication#token-lifecycle) for cancellation and interruption behavior, per-attempt timeouts, and the absence of an overall acquisition deadline. Custom provider futures must complete so that the shared acquisition can finish and later calls can proceed.

## Additions

### JSON object formatting

`Json.prettyPrintObject(String)` formats exactly one complete JSON object. Leading and trailing whitespace are accepted. Arrays, scalars, JSON null, malformed input, additional non-whitespace content, absent input, and blank input are returned unchanged.

This is an additive API change. The corresponding `JsonProvider.prettyPrintObject(String)` method has a default implementation that delegates to `isValidObject()` and `prettyPrint()`, so existing providers do not need a new implementation. Both bundled Jackson providers combine validation and formatting in a single parse. Subclasses that customize the existing methods retain those overrides. See [JSON SPI](../advanced/spi#json-spi) for the provider contract.
