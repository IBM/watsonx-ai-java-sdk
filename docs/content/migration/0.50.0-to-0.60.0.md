---

JSON provider discovery now falls back to the SDK's class loader when the calling thread cannot find a binding. Each Jackson binding also gives `WatsonxJacksonModule` its own package, removing the shared class name and split package introduced in 0.50.0. Applications that import this module directly must update their imports and recompile.

---

## Breaking changes

### Binding-specific `WatsonxJacksonModule` packages

`com.ibm.watsonx.ai.WatsonxJacksonModule` is replaced by a class in each binding's namespace:

| Binding dependency | New module class |
|---|---|
| `watsonx-ai-jackson2` | `com.ibm.watsonx.ai.jackson2.WatsonxJacksonModule` |
| `watsonx-ai-jackson3` | `com.ibm.watsonx.ai.jackson3.WatsonxJacksonModule` |

**Before, with either binding:**

```java
import com.ibm.watsonx.ai.WatsonxJacksonModule;
```

**After, with Jackson 2:**

```java
import com.ibm.watsonx.ai.jackson2.WatsonxJacksonModule;
```

**After, with Jackson 3:**

```java
import com.ibm.watsonx.ai.jackson3.WatsonxJacksonModule;
```

The constructor and mix-in behavior are unchanged. This move breaks source and binary compatibility for code referencing the old class. Update the import and recompile applications and integration libraries against the new SDK. Libraries compiled against the old name must also be rebuilt, even if the application's own source does not import it.
